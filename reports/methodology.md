# Методология: RSRP около культурных объектов Вены

## 1. Данные, задача и очистка

__Задача проекта:__ оценить уровень RSRP около пяти культурных объектов и на обследованной территории Вены так, чтобы расчёты можно было повторить. Notebook, QGIS и Superset используют одни и те же подготовленные данные.

__Данные__: vienna_drive_test.csv, содержат 596 543 строки с измерениями операторов A, B и C за период с 2024-10-13 по 2025-03-08.

### Предобработка
При подготовке числовые поля переведены в числа, а время в формат даты и времени. В 6 038 строках широта и долгота были перепутаны местами. В этих случаях ошибка была однозначной, поэтому координаты исправлены. Для проверки использован прямоугольник 48.0–48.4° N, 16.1–16.7° E, который охватывает Вену.

По очереди удалены 11 961 строка с неверными координатами, 5 914 строк с RSRP от нуля и выше и 268 строк без обязательных данных. Если не хватало только дополнительных показателей, например timing_advance, запись сохранялась. Значение 99 в поле RSRP считалось ошибкой, а не признаком сильного сигнала.

У записей с одинаковым measurement_id сравнивались время, координаты, RSRP и оператор. Для 162 ID эти данные различались. Все 324 строки с такими ID удалены, потому что нельзя определить, какая запись верная. Ещё 602 повтора с одинаковыми основными данными удалены, при этом по одной записи сохранено. После очистки осталось 577 474 уникальных измерений.

Pandas используется для очистки данных и расчёта сводных показателей, GeoPandas - для работы с координатами и геометрией, H3 - для создания сетки, SciPy - для поиска ближайших точек. Файл достаточно небольшой, поэтому Spark и расчёты на нескольких машинах не нужны. Каждый инструмент используется для своей задачи.

## 2. Объекты и расчёты на карте

Для проекта выбраны Technisches Museum, Raimund Theater, Secession, Theater an der Wien и Upper Belvedere. Адреса взяты с официальных сайтов. Объекты выбирались по трём условиям: культурное назначение, понятный адрес и измерения всех трёх операторов рядом.

Координаты по адресам получены через API Яндекса. В geocoding.json сохранены исходный адрес, ответ сервиса, координаты, точность и дата запроса. Для четырёх объектов Яндекс указал точность exact. Для Raimund Theater адрес 18–20 был сопоставлен с домом 18 с точностью number. Ключ API в результаты не включён. Wien Museum исключён, потому что Яндекс указал соседний дом. Вместо него выбран Theater an der Wien, для которого адрес совпал точно. Неиспользованные ответы сохранены отдельно, чтобы выбор можно было проверить.

Точки создаются в системе координат WGS 84: сначала долгота (longitude), затем широта (latitude). Расстояния считаются в EPSG:32633 (UTM 33N). Эта система подходит для Вены и позволяет работать в метрах.

Для оценки сигнала около каждого объекта берутся измерения в радиусе 250 м от точки его адреса. По каждому оператору отдельно считается медиана RSRP. Радиус одинаков для всех пяти объектов: он охватывает ближайшие улицы и не включает далёкие точки. Медиана меньше зависит от отдельных слишком высоких или низких значений, чем среднее. Она считается по значениям в dBm. Средняя мощность в линейных единицах здесь не рассчитывается.

Для каждой из 15 пар «объект - оператор» сохранены медиана, число записей, расстояние до ближайшего измерения и отметка о том, хватает ли данных. Если записей меньше трёх, медиана не рассчитывается. Три записи - это выбранный минимум для расчёта, который сам по себе не гарантирует надёжный результат. Зоны вокруг соседних объектов могут пересекаться, поэтому одно измерение иногда попадает в расчёты для двух объектов. Из-за этого нельзя складывать число записей у всех объектов и считать сумму числом уникальных измерений города.

Территория разделена на ячейки H3 уровня 9. Средняя площадь такой ячейки по миру составляет около 0.105 км², но в конкретном месте она может отличаться. Этот размер позволяет объединить близкие измерения, сохранив различия между небольшими участками. В каждой ячейке отдельно для каждого оператора рассчитаны медиана RSRP и число записей. Если измерений нет, значение ячейке не присваивается.

Для карты оператора A сигнал между точками оценивается по ближайшему измерению. Карта разбита на пиксели размером 100 × 100 м. Для центра каждого пикселя ищется ближайшее измерение из H3-ячейки, где есть минимум три записи. Пикселю присваивается медиана этой ячейки. Если найденное измерение дальше 250 м, пиксель остаётся без значения (NoData).

## 3. Карты, ограничения и итоговые файлы

Карта QGIS показывает оператора A, у которого больше всего записей (289 696). В ней шесть слоёв: очищенные точки измерений, медианы по H3-ячейкам, число измерений в ячейках, растр с оценкой сигнала, культурные объекты и зоны радиусом 250 м вокруг них. Первые три слоя можно включить для проверки. По умолчанию они выключены, чтобы не закрывать основную карту. Фоновая карта OpenStreetMap не входит в эти шесть слоёв.

RSRP разделён на пять диапазонов: ниже −110; от −110 до −100; от −100 до −90; от −90 до −80; не ниже −80 dBm. Во внутренних диапазонах нижняя граница включена, а верхняя нет. Эти круглые значения удобны для сравнения сигнала. Они не являются официальными категориями качества сети.

Для цвета выбрана шкала Cividis: тёмно-синий показывает слабый сигнал, светло-жёлтый - сильный. Там, где оценки нет, видна только фоновая карта. Культурные объекты также различаются по номеру и форме маркера. В Superset у операторов постоянные цвета: A - синий, B - оранжевый, C - пурпурный. Цветовые шкалы выбраны в соответствии с условием от заказчика, который имеет нарушения восприятия красно-зеленого спектра. Для чтения визуализаций проекта не нужно различать красный и зеленый.

В Superset четыре блока: подробная таблица объектов, медианы около объектов, распределение RSRP по интервалам 5 dB и число измерений по датам. Фильтр оператора действует на все блоки. График объектов использует готовые медианы. Функция MAX в SQL берёт единственное сохранённое значение для пары объекта и оператора, поэтому повторного усреднения нет.

Notebook позволяет заново получить файлы CSV, GeoPackage и GeoTIFF. Проект QGIS сохранён вместе с данными и использует относительные пути. Для Superset подготовлены экспорт дашборда и CSV, из которых можно восстановить таблицы в подключённой базе. Методы и параметры расчётов описаны в notebook и этом файле.

Источники адресов: technischesmuseum.at, musicalvienna.at, secession.at, theater-wien.at, belvedere.at. Полные ссылки сохранены в objects.csv. Документация: yandex.ru/maps-api/docs/geocoder-api/; h3geo.org/docs/core-library/restable/; superset.apache.org/docs/. Фоновая карта: OpenStreetMap contributors.

### Ограничения 
Маршруты и даты поездок различаются, а в некоторые дни есть измерения только оператора A. Повторные координаты и остановки автомобиля дают одним участкам больше записей, чем другим. Поэтому измерения нельзя считать независимой случайной выборкой. Данные разных частот и времени объединены внутри каждого оператора. Результаты описывают только этот набор поездок. Оценка по ближайшему измерению не учитывает стены, рельеф и особенности распространения сигнала. Измерения на улицах рядом с адресом не показывают сигнал внутри здания. Поэтому по этим данным нельзя делать общие выводы о качестве всех сетей Вены и принимать решения для всего города.
