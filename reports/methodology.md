# Методология: RSRP около культурных объектов Вены

## 1. Данные, задача и очистка

Задача проекта — подготовить воспроизводимую оценку уровня RSRP около пяти культурных объектов и на обследованной территории Вены. Notebook, QGIS и Superset используют одни результаты подготовки. RSRP характеризует мощность опорного сигнала в dBm: чем значение ближе к нулю, тем сильнее сигнал. Это не полная оценка качества связи или скорости интернета.

Источник — учебный файл vienna_drive_test.csv: 596,543 строк, операторы A, B, C, измерения с 2024-10-13 по 2025-03-08. Названия операторов не раскрываются. Исходный CSV не изменялся; его SHA-256 включён в MANIFEST.json полного архива.

При подготовке числовые поля и время приведены к соответствующим типам. У 6,038 строк однозначно переставлены широта и долгота. Для проверки координат использован прямоугольник 48.0–48.4° N, 16.1–16.7° E, охватывающий Вену. Он служит проверкой ошибок, а не административной границей города.

Последовательно исключены 11,961 строк с неверными координатами, 5,914 строк с неотрицательным RSRP и 268 строк без обязательных данных. Пропуски в дополнительных показателях, например timing_advance, не являются причиной удаления записи. Значение 99 в RSRP является некорректным для этой задачи, а не сильным сигналом.

Для повторных measurement_id сравнивались время, координаты, RSRP и оператор. У 162 ID эти поля различались: все 324 строки таких групп исключены, поскольку достоверную версию выбрать нельзя. Ещё 602 повторов с одинаковыми основными полями свёрнуты. Итого осталось 577,474 уникальных измерений.

Pandas используется для очистки и агрегации, GeoPandas — для координат и геометрий, H3 — для сетки, SciPy — для поиска ближайших точек. Масштаб файла позволяет обойтись без Spark и распределённых вычислений. Смена инструментов связана с конкретной операцией, а не с количеством технологий.

## 2. Объекты и пространственные методы

Выбраны Technisches Museum, Raimund Theater, Secession, Theater an der Wien и Upper Belvedere. Их адреса взяты с официальных сайтов. Критерии выбора — культурное назначение, понятный адрес и наличие измерений трёх операторов поблизости. Выбор не основывался на том, насколько сильный сигнал получился около объекта.

Геокодирование выполнено API Яндекса. В geocoding.json сохранены исходный адрес, ответ, координаты, точность и дата запроса. Четыре объекта получили точность exact; адрес Raimund Theater 18–20 сопоставлен с номером 18, точность number. Ключ API в результаты не включён. Wien Museum исключён после того, как Яндекс вернул соседний дом; замена Theater an der Wien имеет точное адресное совпадение. Неиспользованные ответы сохранены отдельно для проверки выбора.

Точки создаются в WGS 84 в порядке longitude, latitude. Для всех расстояний применяется EPSG:32633 (UTM 33N), поскольку её единицы — метры и зона подходит для Вены. Считать радиус в градусах или в Web Mercator для этой локальной задачи не требуется.

Оценка около объекта — медиана RSRP всех измерений соответствующего оператора не далее 250 м от адресной точки. Радиус одинаков для пяти объектов: он охватывает ближайшие улицы, но ограничивает перенос сигнала издалека. Медиана менее чувствительна к отдельным экстремальным значениям, чем среднее. Используется описательная медиана в dBm, а не средняя физическая мощность в линейных единицах.

Для каждой из 15 пар «объект — оператор» сохранены медиана, число записей, расстояние до ближайшего измерения и статус обеспеченности данными. При менее чем трёх записях медиана не назначается. Три записи — минимальное правило достаточности, а не доказательство статистической надёжности. Буферы соседних объектов могут пересекаться: одно измерение может участвовать в двух локальных оценках. Суммировать эти числа как уникальные измерения города нельзя.

Для территории используется H3 resolution 9: средняя мировая площадь такой ячейки около 0.105 км², а локальная площадь может отличаться. Этот масштаб подходит для обобщения близких измерений без чрезмерно крупных зон. В каждой ячейке отдельно по оператору рассчитаны медиана RSRP и число записей. Пустые ячейки не получают наблюдаемого значения.

Для карты A построена ограниченная оценка ближайшим соседом. В центре пикселя 100 × 100 м находится ближайшее измерение из H3-ячейки минимум с тремя записями; пикселю назначается медиана этой ячейки. Если до поддержки более 250 м, остаётся NoData. Значение не сглаживается и не оценивается для всей Вены. Размер пикселя — параметр отображения, а не точность исходных координат.

## 3. Визуализация, ограничения и передача

Карта QGIS посвящена оператору A, у которого больше всего записей (289,696). Шесть слоёв имеют разные функции: исходные очищенные точки, наблюдаемые H3-медианы, число измерений в H3, оценочный растр, культурные объекты и 250-метровые буферы. Первые три доступны для проверки, но первоначально выключены, чтобы не закрывать основную карту. Подложка OpenStreetMap не входит в число содержательных слоёв.

RSRP показан пятью фиксированными диапазонами: ниже −110; от −110 до −100; от −100 до −90; от −90 до −80; не ниже −80 dBm. Нижняя граница каждого внутреннего диапазона включена, верхняя исключена. Это понятные круглые интервалы для сравнения значений, а не нормативные категории качества сети.

Использована последовательная шкала Cividis: тёмно-синий соответствует слабому сигналу, светло-жёлтый — сильному. Увеличение яркости связано с усилением сигнала; различение не опирается на красный и зелёный. Без оценки видна подложка без сигнальной заливки. Номер и форма маркера дополнительно обозначают культурный объект. Для операторов в Superset применены постоянные цвета: A — синий, B — оранжевый, C — пурпурный. Таблица не использует красно-зелёные полосы.

Superset содержит четыре блока: подробную таблицу объектов, медианы около объектов, распределение RSRP по интервалам 5 dB и число измерений по датам. Фильтр оператора связывает блоки. Для графика объектов используется уже рассчитанная медиана; MAX в SQL извлекает единственное подготовленное значение для пары объекта и оператора, а не заново усредняет наблюдения.

Ограничения: маршруты и даты обследования различаются, некоторые даты представлены только оператором A. Повторные координаты и остановки автомобиля влияют на вес участков; записи не являются независимой случайной выборкой. Частоты и времена объединяются внутри оператора, поэтому оценки описывают именно этот набор поездок. Перенос ближайшим соседом не учитывает стены, рельеф и физику распространения. Адресная точка и окружающие улицы не заменяют измерения внутри здания. Эти ограничения не позволяют делать управленческие выводы о качестве всех сетей города.

Передача: notebook воспроизводит CSV, GeoPackage и GeoTIFF. QGIS-проект сохранён с относительными путями вместе с данными. Для Superset предоставлены экспорт dashboard и CSV для восстановления таблиц в подключённой базе. Методология и параметры содержатся в notebook и этой записке.

Источники адресов: technischesmuseum.at, musicalvienna.at, secession.at, theater-wien.at, belvedere.at. Полные ссылки сохранены в objects.csv. Документация: yandex.ru/maps-api/docs/geocoder-api/; h3geo.org/docs/core-library/restable/; superset.apache.org/docs/. Подложка: © OpenStreetMap contributors.
