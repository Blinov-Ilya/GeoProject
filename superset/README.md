# Отчёт Superset

Четыре блока: таблица объектов с радиусом сопоставления, медианы RSRP около объектов, распределение измерений по RSRP и число измерений по датам. Фильтр оператора применяется ко всем блокам. Чем RSRP ближе к нулю, тем сильнее сигнал.

## Первый запуск

1. Подготовьте PostgreSQL и базу для данных отчёта; пользователь должен иметь право создавать схему и таблицы. Для загрузки нужны Python 3 и клиент `psql` (`postgresql-client` в Ubuntu). Дополнительные Python-библиотеки загрузчику не нужны.
2. Успешно выполните notebook, чтобы получить актуальные CSV в `output/`.
3. Из корня проекта выполните:

   ```bash
   export DATABASE_URL='postgresql://USER:PASSWORD@HOST:5432/DBNAME'
   python3 superset/load_data.py
   ```

4. В Superset импортируйте `superset_dashboard.zip` через **Dashboards → Import**. Для существующего отчёта разрешите перезапись. Драйвер PostgreSQL должен быть установлен в окружении Superset: `psycopg2-binary`; проверена версия Superset 6.1.0.
5. В **Settings → Database Connections** откройте импортированное подключение **Vienna drive tests**, укажите адрес и пароль вашей БД. В ZIP сохранён адрес `db:5432/superset` из исходного локального стенда: замените его, если окружение другое. Superset и загрузчик должны обращаться к одной базе; сетевые адреса из контейнера и с хоста могут различаться.
6. Откройте `/superset/dashboard/vienna-rsrp/`. Должны отображаться ровно четыре графика с соответствующими заголовками. Выберите A и нажмите **Apply filters**: в таблице останутся записи этого оператора.

## После изменений notebook

Повторите успешный расчёт, затем `python3 superset/load_data.py` и обновите дашборд. Переимпортировать ZIP не требуется. Кэш данных графиков и datasets отключён: сводные таблицы небольшие, а после обновления нужны свежие значения. Если notebook сообщил, что экспорт пропущен, CSV могут остаться от прошлого запуска: сначала устраните причину.

Загрузчик читает три файла, выбирая столбцы **по именам**. Порядок и дополнительные столбцы могут меняться. Все три таблицы обновляются одной транзакцией; при ошибке прежние данные сохраняются.

| CSV в `output/` | Обязательные столбцы |
|---|---|
| `object_signal.csv` | `object_id`, `name`, `address`, `operator`, `median_rsrp_dbm`, `measurement_count`, `nearest_distance_m`, `status`, `radius_m` |
| `rsrp_distribution.csv` | `operator`, `rsrp_bin`, `measurement_count` |
| `daily_counts.csv` | `survey_date`, `operator`, `measurement_count` |

`rsrp_bin` — нижняя граница интервала в dBm; `survey_date` — дата `YYYY-MM-DD`. Для объекта должна быть одна строка на пару «объект — оператор». Названия файлов, обязательных полей, их типы и смысл — интерфейс между notebook и отчётом. Их переименование или изменение смысла нужно согласовать; изменения реализации расчётов этого не требуют. Радиус не зафиксирован в заголовке: он показан из данных. Скриншоты — пример, при изменении данных их нужно обновить.

Готовый `deliverables/submission.zip` — отдельный снимок проекта. Перед сдачей пересоберите его **после** слияния изменений notebook, включив актуальные файлы `superset/`, отчёты и выполненный notebook. Замена файлов в рабочей папке не обновляет этот архив автоматически.
